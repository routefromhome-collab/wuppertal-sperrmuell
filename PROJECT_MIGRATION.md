# PROJECT_MIGRATION.md: технический журнал

Старый репозиторий `routefromhome-collab/sperren-map` остаётся нетронутым (источник кода, данных, логики).

## Решения

- Frontend: чистый JS/HTML/CSS без сборщика, Leaflet, хостинг GitHub Pages.
- Backend: Python на GitHub Actions, данные в JSON внутри репозитория. Replit исключён полностью.
- Сохранено: логика AWG, геокодирование (фильтры улиц, рамка города), маршруты по 20 точек, Telegram-канал.
- Правило D-1 сохранено и покрыто тестами (Python и JS).
- Автопубликации по расписанию нет: список в канал выходит только когда админ нажимает «Отправить» в приложении (Worker) или запускает workflow Publish.
- Публикация из приложения: Cloudflare Worker проверяет initData и ADMIN_IDS, публикует по одному дню, не публикует даты вне календаря AWG.
- Формат поста сохранён как в рабочем main.py (только названия улиц); карты по домам: координаты домов из старого geocode_cache.json (data/source/house_coords_seed.json).
- v1 без аккаунтов, избранного и подписок.

## Что изменено относительно main.py

| Было | Стало | Почему |
|---|---|---|
| POST на каждую пару «улица × день» | один запрос на улицу, все даты сразу | ~7× меньше запросов к AWG |
| 60 параллельных запросов, пауза 0.01 с | 6 потоков, общий лимит ~8 запросов/с, backoff | риск блокировки IP |
| aiohttp + python-telegram-bot + pandas + folium | requests + bs4 (+ openpyxl только для импорта) | меньше зависимостей |
| 2-opt как для замкнутого тура | 2-opt для открытого пути | на последней позиции старый код учитывал несуществующее ребро к старту |
| части маршрута независимы | следующая часть начинается с последней точки предыдущей | маршрут не рвётся на стыке |
| `quote()` с `safe="/"` | `safe=""` | имена с `/` не ломают URL |
| токен GitHub в URL для push | коммит из workflow через GITHUB_TOKEN | секреты не светятся в командах |
| статичные HTML-карты на каждую дату | одно приложение, данные в JSON | не растёт число файлов |
